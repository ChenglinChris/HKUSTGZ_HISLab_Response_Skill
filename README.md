# HKUSTGZ_HISLab_Response_Skill

用于期刊审稿意见逐条回复与手稿最小化修订的研究写作辅助 Skill。说明以中文为主，回复模板与示例采用英文，覆盖证据核查、回复信版式、逐点回应、引文与高亮双向审计、统计事实红线及交付检查。

本项目是研究写作辅助工具，不代表任何机构的官方背书。作者须对事实、分析、引用、期刊要求及最终提交负责。MIT 许可证见 [LICENSE](LICENSE)。

## 安装

将仓库中的整个 `hkustgz-hislab-response-skill` 目录复制到标准用户级 skills 目录，最终结构必须为：

```text
~/.agents/skills/hkustgz-hislab-response-skill/SKILL.md
```

Windows 的 `~` 指当前用户主目录；也可使用宿主明确支持的项目级 `.agents/skills/`。安装后按宿主要求刷新技能发现或重启会话，确认其实际读取了文件。不要覆盖已有同名安装而不先比较、备份并征得许可。

可从 GitHub 仓库下载并解压后复制上述 Skill 目录；若版本发布页提供 ZIP，也应先核对其来源和内容，再将 ZIP 中的 Skill 目录放到标准路径。GitHub URL 是文件来源，不自动等于宿主可直接调用的原生 Skill。

## 用法与人工审阅

1. 明确指定要处理的稿件、审稿意见、回复信及允许修改的文件，不要让 agent 猜测目标。
2. 先提供并核查分析代码、数据来源、实验记录和文献证据；资料不足时列出缺口，不推测不存在的实验或参数。
3. 按规则逐点回复、最小化修订，并对回复摘录、手稿高亮、统计值和引用做双向核对。
4. 不得无依据改动结果；证据支持的纠错须记录依据与影响，同步全部相关文件。不得捏造数据、实验、引用或审计通过记录。
5. 人工审阅后才提交。期刊/编辑明确要求与本模板冲突时，应说明冲突并按适用要求调整，不以模板规避必要纠错或透明报告。
6. 不自动上传稿件、数据或审稿意见到 GitHub 或其他外部服务；任何对外传输须另获用户明确授权。

## 发布副本的必要调整

相对于原有通用规则，发布副本保留约 230 行主体与核心工作流，仅做以下必要调整：

- 统一 frontmatter 标识、Skill 目录名与展示标题。
- 将真实修回来源表述改为通用教学反例，不携带具体稿件数据或个人路径。
- 在核心原则、手稿规则及数值验收项中明确：不得无依据改动统计结果；证据支持的纠错须留痕并同步全部相关文件。保持结果完整性不等于保留已证实的错误。
