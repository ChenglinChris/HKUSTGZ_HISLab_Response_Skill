# HKUSTGZ_HISLab_Response_Skill

本手册把「撰写 Response to Reviewers + 同步最小化修订手稿」的标准动作、版式规格、红线与验收清单固化下来，是一份可复用技能文档。使用时把方括号中的示例槽位替换为目标论文的实际内容即可（见文末「复用方式」）。

## 1. 适用范围与核心原则

**适用范围**：期刊修回阶段（major revision / minor revision），需要逐条回复审稿人并同步修改稿件的工作；也可用于编辑意见、格式审查意见的回复。

**五条核心原则（任何操作不得违反）**：

1. **最小修改**：能用澄清、解释、补充一句说明解决的，不动段落；能改一句话解决的，不改结构。改动越少，评审风险越低。
2. **能解释不补实验**：审稿人建议的新实验、新分析，如果不在当前研究定位之内，优先用「现有证据 + 理由 + 局限说明」回应，而不是补做。补做意味着新数据、新结论与新的风险面。
3. **不得无依据改动统计结果**：修回不得无依据改动统计数值、检验统计量、p 值、置信区间、图表数值；通常只修改文字表述、限定条件与解释口径。证据支持的纠错须记录依据与影响，并同步全部相关文件（含手稿、图表、回复信及分析输出）。
4. **不虚构未做之事**：绝不声称做过未做的操作。设备型号未确认、预处理参数无记录、效应未处理——全部按事实表述（见第 6 节）。
5. **受众规则（response 与 manuscript 都是写给审稿人/编辑看的）**：两份文件都是面向审稿人与编辑的成品，作者内部的编辑动作话语不得出现——例如「The corresponding limitation has been removed from the Limitations section」「we deleted/removed the sentence/limitation」「has been deleted from the reference list」这类自述删改表述。需要交代改动时，改写为面向审稿人的解释：直接讲理由与做法（现在怎么写、为什么这样写），不叙述「删了什么」；说明稿件当前状态用「now includes / now states / is no longer used」式写法。这类解释只放在 response 的科学论证中；既不需要进 response、也不需要进 manuscript 的内部决策一律不写。（配套规则见第 3 节第 10-12 条、第 5 节第 11 条）

## 2. 回复信格式与版式规范

以下为通用模板（经实践认可的版式），可直接套用。

### 2.1 版式规格

- 字体：Calibri 10.5；纸张 A4；页边距上下 2.54 cm、左右 3.175 cm；无页眉页脚。
- 定位修改位置**只用「章节号 + 章节名」**（如 3.2 Procedure），不用页码、不用行号。
- 定位标签只写「章节号+章节名」（如 "3.7 Statistical Analysis:"），**不加 "Section" 前缀**；但 **Response 正文行文中指称章节时必须保留 "Section"**（如 "in Section 3.2"、"Section 3.7 describes …"）——只有摘录的定位标签省略 "Section"，行文引用不省略。
- 每位审稿人单独一页（审稿人之间插入分页符）。
- 高亮颜色约定：每位审稿人分配一种高亮色，并在该审稿人的引导句（致谢段）里说明，例如：
  `In the revised manuscript, changes made in response to Reviewer 1 are highlighted in yellow, and changes in response to Reviewer 2 are highlighted in green.`

### 2.2 结构骨架

```text
RESPONSES TO REVIEWERS

Manuscript ID: [稿号]                 <- 无稿号则整行省略
Title: [Manuscript Title]

**We sincerely thank the editor and the reviewers for their constructive
comments, which have helped us improve this manuscript substantially.**   <- 简短加粗致谢：仅致谢，不列改动清单

[分页符]

**Reviewer 1:**                       <- 审稿人标签加粗，单独起页

**Comment 1:** The authors should clarify how the experimental
conditions were operationalized and reported.        <- 审稿人原话逐字保留（Courier New），Comment 标签加粗；不替审稿人改写、不拆分、不合并

<u>Response:</u> We thank the reviewer for this comment. Based on [reason], we have revised [object] in Section 3.2 (Procedure). The revision reads:      <- Response: 标签加下划线

    **3.2 Procedure.** "*We additionally report how each condition was operationalized in the procedure description.*"
        <- 修改引文：加粗「章节号+章节名」；斜体引号内为修改句；左缩进

**Comment 2:** ...                     <- 同一审稿人下一条意见

<u>Response:</u> This is the same point raised by Reviewer 2 (Comment 3); please see our response there.     <- 重复意见简短回指

[分页符]

**Reviewer 2:**

**Comment 1:** ...
```

### 2.3 样式规则速查表

| 元素 | 样式规则 |
| --- | --- |
| 首部标题 | `RESPONSES TO REVIEWERS` |
| 稿号 | 有则写 `Manuscript ID: ...`，无则省略该行 |
| 标题行 | `Title: [论文标题原文]` |
| 致谢段 | 加粗、简短；只致谢，不列改动清单 |
| `Reviewer N:` | 加粗；每位审稿人单独一页（分页符） |
| `Comment N:` | 标签加粗；评论原文逐字复制、Courier New；不替审稿人改写、不拆分 |
| `Response:` | 标签加下划线 |
| 修改引文 | 加粗「章节号+章节名」+ 斜体引号内修改句 + 左缩进 |
| 正文 | Calibri 10.5；A4；边距上下 2.54 cm、左右 3.175 cm；无页眉页脚 |
| 定位方式 | 只用章节号+章节名，不用页码/行号 |
| 高亮色 | 每位审稿人一种颜色，在引导句中说明 |

## 3. 回复写作策略

1. **总体评价只简短致谢**：审稿人对整篇论文的总结性评价，回应一句感谢即可，不罗列改动清单（改动清单已在各条目中体现）。
2. **普通问题 1-3 段**：结构为「致谢/同意 → 理由或做法 → 修改位置与摘录」。超过 3 段通常意味着在解释而非回应。
3. **正文已修改的内容不再重复解释**：用固定句式交代「为什么改、改在哪」，随后直接放摘录。参考口径：
   - 中文：「我们感谢/同意审稿人的意见。基于 [理由]，我们在 [章节号+章节名] 对 [对象] 进行了修改，具体修改如下：」+ 摘录。
   - 英文：`We thank the reviewer for this comment. Based on [reason], we have revised [object] in [N] ([Section Name]). The revision reads:` + 摘录。
4. **一条 Comment 含多个议题**：在同一条 response 内按 (1) (2) (3) 依次处理；不把审稿人的一条意见拆成多条 Comment。
5. **重复意见**：简短回指即可，例如 `This is the same point raised by Reviewer 1 (Comment 3); please see our response there.` 不重复展开。
6. **不采纳新增分析时**：三步走——先认可价值（`We agree that ... would be valuable`），再说明当前研究定位（`the present study focuses on ..., and was designed as ...`），最后降调主张或补写局限。**禁止只写「超出研究范围」（out of scope）**——那是拒绝，不是回应。
7. **引用文献**：统一放在对应条目下，或统一放在回复信末尾（如 References 区）；两种方式择一，全篇保持一致。
8. **事事有回应**：审稿人提出的每一个点（含编号子点如 (i)(ii)、多议题意见中的每个议题）都必须逐一明确回应，不得遗漏、不得只答部分；多议题意见可在同一条 Response 内分点依次回应；验收时逐点核对审稿意见与回复一一对应（见第 8 节第 11 项）。
9. **不主张的观点直接删提及，不写单独否定**：审稿人指出、而作者不打算主张的观点（如预测能力、因果解释、跨条件等价/泛化），manuscript 中只做删除或改为正面关联表述，不在正文写「本研究不验证/不声称×××」式自指免责句；此类解释只写在 response 正文，不写进手稿（与第 5 节第 10 条配套；验收见第 8 节第 12 项）。
10. **设计选择的标准做法类 claim 须附权威参考文献（先核实）**：凡在 response 中声明「本实验的做法属于标准做法/常规程序/既有实践」的句子，必须附经核实的文献；引用前用 Crossref/PubMed 核对作者、年份、期刊、DOI，并确认该文献确实支持所引说法（支持范围），不得超范围引用；优先选用已在本稿参考文献中的文献。
11. **自有方法论/设备/代码/模型描述通常不加参考文献**：对本实验自己的程序、设备、代码、模型的描述一律自述即可，不因写作时参考过文献而加引注（软件/工具包引用如 NeuroKit2（Makowski et al., 2021）、经典定义引用如 PERCLOS（Wierwille et al., 1994）除外）。
12. **引文引导语统一，禁用内部字样**：修改引文统一用 “The revised text is as follows:”（或 “The revised and related text is as follows:”）引导；**“Changes in the manuscript:” 列为禁用语**，不得在回复信中出现（也不得出现等价的内部工单式字样）。
13. **新增参考文献置于该条回复末尾**：每条 comment 的回复中如需新增参考文献（References），必须集中放在该条回复的最后，即所有 Response 正文与修订摘录之后，不要放在理由段落与修订摘录之间，也不要分散插入其他位置；格式为条末的 “References:” 列表，每条按「作者, 年. 标题. 期刊, 卷(期), 页. DOI」著录。验收见第 8 节第 13 项。
14. **重叠 comment 的回复口径一致性**：审稿人的 comments 常存在重叠——可能出现在不同审稿人之间、major 与 minor 之间，或同一位审稿人内部。撰写某条回复前先定位与之重叠的其他条目，各条回复对同一修改的描述必须口径一致——指向相同的修改位置与相同的结论方向、使用相同术语（如同一处操作、同一处措辞、同一结论名称），不要求逐字相同；并在相关回复中以 “Please see also our response to Major Comment N.” 形式交叉引用对应条目（重复意见亦可直接回指，见第 5 条）。重叠回复之间不得出现互相矛盾的声称（亦不得与稿件现状不符），例如一边称某项信息「未记录/未说明」、另一边称「已描述/已扩展」。口径核对后若发现矛盾，以覆盖更全或更新的回复为准，并同步修正其他处（验收见第 8 节第 15 项）。

## 4. 引文最小化规则

1. **只引用实际发生修改的句子**；未修改的句子一律不进引文。
2. **引文 = 高亮（句级对应，硬规则）**：引号内文字与 manuscript 高亮（含新增）内容必须完全一致，不能多也不能少，以句子为单位；引文的最小单位是完整句子，不得只引半句、也不得把未高亮的文字混进引号内。
3. **未改动内容才可用省略号 `…` 替代**：省略号只能替代未改动的文字，省略号处不得是任何被高亮（改动/新增）的内容；引文从句中开始、或以句中结束，则两端加 `…`；跨句跳过未改动内容时用 `…` 连接。
4. **一条修改涉及连续多个新句时必须整段引用**：对应摘录必须覆盖该修改的全部新句（内容较长时可拆为相邻的多条摘录，其并集必须覆盖全部新句）；不得用省略号截断高亮句子，也不得在相邻高亮句之间用省略号跳过。
5. **新增的整句、整段可以完整引用**（不受省略号规则限制，但须同时满足第 2、4 条）。
6. **每条引文必须与最终稿件逐字一致**：引文写完、正文改完后，回到修订稿逐字比对（见第 8 节审计项）。
7. **删除型修改只引用「改后」的文字**：即删除后该处现在读作什么，就引用什么；不要把被删掉的句子放进引文。
8. **双向一一对应（硬规则）**：每条修改必须两个方向同时成立——(1) response 侧：在该修改的**对应条目**中，把改后文字完整写进摘录；(2) manuscript 侧：对同一段文字加对应高亮（颜色按审稿人分配）。缺任何一侧都视为未完成。审计双向都要过：**每个高亮 span 必须被至少一条引文片段覆盖**；**每条引文（非省略号）片段必须在正文中存在且对应文字处于高亮状态**。整体新增的小节/段落，其标题与新正文都要纳入对应关系（标题可用条目中的章节标签对应，正文必须整段覆盖）。
9. **整体新增的小节/段落必须整段引用**：不得只引一部分；内容较长时可拆为相邻的多条摘录（可分段引用），但新增部分的每一句都必须出现在引文中，且引文的裁剪不得吞掉任何被高亮的文字。
10. **两个方向的修正方向相反**：引文只可省略**未改**内容（省略号处不得是修改内容）；若高亮越过了修改边界（覆盖到未改文字），属于残留高亮，按第 5 节第 3 条取消，而不是用引文去凑。

示例：

```text
新增整句（可完整引用）：
    4.2 Results. "We additionally report the descriptive statistics for each condition."

段中修改（前后未改内容用 … 省略）：
    2.3 Measures. "… the questionnaire was administered at three time points …"

删除型修改（只引改后文字；例如原句含因果性表述，修改后读作）：
    5.1 Discussion. "… the observed pattern should be interpreted as an association …"
```

## 5. 手稿修改规则

1. **保留原期刊版式**：使用投稿时的模板与样式；不套用其他期刊模板（会引入无法解释的格式差异）。
2. **最小修改**：只动必要句子与词；非目标段落保持逐字节不变。
3. **高亮只覆盖真正改动/新增的文字**；未改文字必须取消高亮。docx 中高亮是 run 级属性，修订完成后必须**逐 run 对照原稿审计**（段落「看起来」没高亮不代表 run 没有残留）。
4. **共同修改只标一次**：同一处文字若同时回应多位审稿人，只保留一种高亮（不叠色），并在各审稿人引导句或条目中说明对应关系。
5. **全文主张统一调整**：例如把预测性主张降调为关联性主张时，摘要、引言、讨论、结论必须一起改，并同步调整研究问题/目标的表述，避免「结论已降调、引言仍在承诺预测」。
6. **术语统一**：同一对象全文统一用词（示例：eye-tracking 数据不得与 physiological signals 混称；观测变量与操纵因素不得混称）。
7. **不得无依据改动统计数值/表/图**：表中数值、图注、检验统计量不得无依据改动；如审稿人要求补充描述性统计，可新增文字或新表。证据支持的纠错须记录依据与影响，并同步全部相关文件。
8. **高亮与引文双向对齐（与第 4 节第 8-10 条配套）**：修改完成后必须对全文做双向审计并修复到一一对应——(a) 正文已高亮但回复信未引用（a 类）：在对应条目摘录中补全该句，整段新增的整段引用（可分段）；(b) 回复信已引用但正文未高亮（b 类）：确属实质改动的补对应颜色高亮，引用的是未改文字的删除该引用片段；(c) 实质改动但既未高亮也未引用（c 类）：补引用并补高亮；(d) 高亮覆盖了未改文字的残留（d 类）：取消多余高亮。共同修改只标一次（第 4 条）不豁免本条的对应关系，需在相关条目中说明对应。
9. **结构性与排版性变化单独记录**：纯空格/标点修复、章节机械重新编号（如因插入新小节导致原「2.4」变「2.5」）、随文引用删除而同步删除参考文献条目等，不属于内容修改；在审计记录中单列，不进入引文与高亮的一一对应（但必须在回复信正文中说明，或按需在相关条目注明）。
10. **不主张的观点直接删提及，不写单独否定（与第 3 节第 9 条配套）**：需要撤回的 claim，直接删除该观点的提及（或保留正面关联表述、删去否定从句并修补语法）；不得在正文写「this study does not aim to / does not establish / not validated as / should not be interpreted as / no … is assumed or established」式自指免责句。此类解释只写在 response 正文；被删文字同步取消其高亮，删后重跑引文-高亮双向审计（第 8 节第 2、9、10 项）。
11. **Limitations 条目不超过 6 条**：Limitations 小节的条目数（含收尾句）最多 6 条，保持精炼、只列仍成立且必须承认的局限；审稿人指出的多条批评若已直接落实到正文，不再逐一作为局限罗列，在对应回复中说明其处理位置即可（与第 1 节第 5 条受众规则、第 3 节第 10-12 条配套）。

## 6. 统计与事实表述红线

- **操纵因素 ≠ 观测解释变量**：区分实验操纵因素（manipulated factor，如实验条件）与观测解释变量（observed explanatory variable，如问卷得分、行为指标）。表格中的 `Independent Variables` 等表头可以保留，但必须加表注说明其含义：哪些是操纵的、哪些是观测的、各自如何进入模型。
- **观测解释变量不做因果解释**：关联性研究中只能写 `associated with / related to`（与…相关），不得写 `causes / leads to / affects / improves`（导致/改善）。
- **交互不显著 ≠ 跨条件等价**：不得写 `no difference between conditions`、`the effect generalizes across ...`。正确写法是描述检验结果本身：`No statistically significant interaction was detected between ... and ...`。
- **边缘 p 值结果降调**：`p` 处于边缘区间（如 .05 < p < .10，具体按目标期刊惯例）的结果降调表述、不放入核心结论；如需报告，注明不确定性。
- **如实描述重复测量实现**：按实际代码写模型设定。示例：若代码中 AR(1) 结构未按 session 重置、模型没有随机截距，就必须如实承认；不得写「已考虑/已处理 session 内的相关性」这类未发生的处理。
- **资料缺失 ≠ 实验未做**：任何没有记录的操作或参数，写 `The available documentation does not specify ...`（现有资料未明确说明），绝不写 `... was not performed / not collected`。二者的举证责任完全不同。
- **文献做法 ≠ 本实验做法**：文献中的常规算法、默认参数、通行流程，不得改写成本实验的实际做法；本实验只能写有证据支持的部分。
- **早停填充值 ≠ 真实观测**：提前终止后用于补齐的填充值不得当作真实观测参与描述或推论；如必须报告，注明其来源与填充规则。

## 7. 撰写前证据核查清单

**总原则：先查再写**。动笔前先查实际分析代码、数据、实验记录、问卷回收记录；写每条事实性陈述时问一句「出处在哪里」。

| 待核实项（示例） | 主要出处 | 状态 |
| --- | --- | --- |
| 设备型号 / 采样率 | 实验记录、采购记录、代码配置 | 已确认 / 部分确认 / 仍缺 |
| 预处理参数（滤波、插值、剔除规则） | 分析代码、处理日志 | 已确认 / 部分确认 / 仍缺 |
| 早停次数与停止准则 | 训练日志 | 已确认 / 部分确认 / 仍缺 |
| 缺失窗口（缺哪些时段/试次） | 数据文件、对齐脚本 | 已确认 / 部分确认 / 仍缺 |
| 量表时点（何时发放/回收） | 问卷平台记录、实验流程文档 | 已确认 / 部分确认 / 仍缺 |
| 用量（样本量 / 时长 / 试次数） | 数据、伦理申请材料 | 已确认 / 部分确认 / 仍缺 |

**三档状态定义与写作口径**：

- **已确认**：有直接出处（代码/记录/数据可直接指向）。正常写入。
- **部分确认**：只有间接或片段证据。只写被证据支持的部分，并标明限定条件。
- **仍缺**：无记录。按 `available documentation does not specify` 口径写（见第 6 节），不猜测、不补脑。

**文献核查**：引用前核实作者、年份、期刊、DOI；并核实该文献**确实支持**所引观点（支持范围），不得超范围引用（如把方法类文献当结论类证据）。

## 8. 程序化验收清单

修回交付前逐项执行；每项都要有可重复的方法，不靠目测。

| # | 验收项 | 方法 |
| --- | --- | --- |
| 1 | 全部审稿意见逐字覆盖 | 用脚本把审稿意见原文与回复信中的 Comment 逐条比对：数量一致、每句逐字一致、无拆分改写 |
| 2 | 每条引文在修订稿中逐字存在 | 抽取回复信中的每条引文，在修订稿文本中做逐字字符串比对 |
| 3 | 统计数值 / F / p / CI token 不得无依据改动 | 修订前 vs 修订后做 token 级 diff；通常只允许文字改动，证据支持的纠错须逐项记录依据、影响与全部相关文件的同步核对结果 |
| 4 | 高亮与真实改动一致 | 逐 run 审计：高亮 run 必须属于新增/修改内容；未改文字的 run 高亮必须为空 |
| 5 | 非目标段落逐字节不变 | 未涉及段落的 diff 必须为空 |
| 6 | docx postcheck | 校验文档结构（可打开、段落/表格结构完整） |
| 7 | 渲染验收 | LibreOffice 转 PDF 后逐页视觉检查：分页、字体、缩进、高亮、无页眉页脚 |
| 8 | 备份纪律 | 原文件不覆盖；原地修改前先备份（除非用户明确说不要备份） |
| 9 | 双向一一对应·高亮→引文 | 逐高亮 span 检索回复信全部摘录片段，要求每个 span 被至少一条片段完整覆盖（允许空白接缝）；未被覆盖的 span 即 a 类错配，必须补引文或按 d 类取消高亮 |
| 10 | 双向一一对应·引文→高亮 | 每条引文（非省略号）片段在修订稿中定位，核对该位置文字处于高亮状态且位置正确；引用的是未改文字或对应处无高亮即 b 类错配，删除该片段或补高亮 |
| 11 | 逐点覆盖核对 | 审稿意见每个子点均有对应回应：把每条意见拆解为要点（含编号子点如 (i)(ii)、多议题意见中的每个议题），逐点在回复信中定位对应回应；有子点缺回应或只答部分即不通过（对应第 3 节第 8 条） |
| 12 | manuscript 无自指免责句残留 | 按短语清单扫描修订稿（does not aim to validate / do not test the ability / not validated as / does not establish / should not be interpreted as / should not be regarded as / no … is assumed or established 等），逐条核对是否属于允许保留的类别（真实结果句、事实性文档说明、样本/设计局限）；出现未清理的自指免责句即不通过（对应第 3 节第 9 条、第 5 节第 10 条） |
| 13 | 新增文献位于该条回复末尾而非中途 | 逐条检查含新增参考文献的回复：文献须集中为条末的 “References:” 列表，位于该条所有 Response 正文与修订摘录之后，每条按「作者, 年. 标题. 期刊, 卷(期), 页. DOI」著录；文献出现在理由段落与摘录之间或分散插入正文其他位置即不通过（对应第 3 节第 13 条） |
| 14 | 引文覆盖 = 高亮覆盖（句级比对） | 把回复信每条摘录与 manuscript 高亮逐句比对：(a) 引文中的每一句必须能在正文定位到处于高亮状态的同句文字（不多不少）；(b) 每条修改涉及的连续多个新句必须被对应条目的摘录整体覆盖（可拆多条，并集须覆盖全部新句）；(c) 引号内出现未高亮文字、或用省略号截断高亮句子、或在相邻高亮句之间以省略号跳过，即不通过（对应第 4 节第 2、3、4 条） |
| 15 | 重叠意见回复一致性核对 | 逐条识别相互重叠的 comments（不同审稿人之间、major 与 minor 之间、同一位审稿人内部），建立重叠组清单（含重叠关系不显式的条目），抽取同组各条回复的正文与摘录逐项比对：指向的修改位置一致、结论方向一致、术语一致、交叉引用编号正确（“see our response to Major Comment N”指向真实存在的条目）；发现矛盾口径（含与稿件现状不符的声称，如一边称某项信息未记录、一边称已描述）即不通过（对应第 3 节第 14 条） |

## 9. 工作流顺序

1. **核实证据**：跑第 7 节清单，标定「已确认/部分确认/仍缺」。
2. **确定逐点回复口径**：先列要点表（审稿意见 → 改/不改 → 改哪个章节 → 理由 → 引用文献），先定口径再动笔。
3. **按模板写 response**：按第 2 节版式、第 3 节策略逐条撰写；引文遵守第 4 节规则。
4. **同步改 manuscript**：按第 5 节规则最小化修改，边改边记录改动清单。
5. **引文与高亮审计**：执行第 8 节第 1-5 项。
6. **渲染验收**：执行第 8 节第 6-7 项。
7. **留存记录**：保存原稿备份、改动清单、审计脚本输出，便于日后回溯「改了什么、为什么改」。

## 10. 教训清单（反例 → 正确做法）

以下为通用教学反例，不指向任何具体稿件、研究或真实修回记录；写作与审计时逐条自查。

| # | 反例 | 正确做法 |
| --- | --- | --- |
| 1 | 回复与正文重复啰嗦：response 里大段复述正文已写的解释 | response 只写「理由 + 改在哪 + 摘录」；解释留给正文 |
| 2 | 把未确认设备写成型号：仅凭资料里一次提及就把某设备型号写进方法 | 未确认的写 `The available documentation does not specify the device model`；只写被证据支持的描述 |
| 3 | 把资料缺失写成「实验未做」：因找不到记录就写 not performed | 写 `available documentation does not specify`，不写 `not performed` |
| 4 | 高亮覆盖未改文字：整段泛黄/泛绿，未改动句子也被高亮 | 高亮只覆盖真正改动/新增；未改文字清除高亮；完成后逐 run 审计 |
| 5 | 引文与正文不同步：正文改了措辞，回复信引文还是旧句 | 每条引文写完后逐字回稿复核；正文任何改动后重跑引文审计 |
| 6 | 把交互不显著写成「证明跨条件泛化/等价」 | 写 `No statistically significant interaction was detected`；不做等价性断言 |
| 7 | 正文新增后忘了更新其他条目引文：补写一段后，引用该段的旧条目失效 | 每次正文改动后重跑「引文-正文逐字比对」（第 8 节第 2 项） |
| 8 | 以「保持估计不变」为理由拒绝描述性统计：审稿人要求补描述统计，作者以「不改动模型估计」为由拒绝 | 描述性统计不改变任何推断数值，应当补充，并在回复中说明原有推断结论未变；把「估计不变」当拒绝理由会被视为回避 |

## 复用方式

1. 复制本文件到目标项目目录（或你的技能/模板目录），按需改名（例如 `Reviewer_Response_SKILL.md`）。
2. 逐条替换正文中的方括号槽位（稿号、标题、章节号+章节名、示例引文）为本论文的实际内容。
3. 第 7 节证据核查表按目标研究的实际待核实项重列（设备、代码、问卷记录等），三档状态逐一标定。
4. 第 8 节验收清单直接作为交付前检查表执行；审计脚本按目标稿件的文本抽取方式调整。
5. 第 10 节教训清单保留为「写前读一遍、写后对一遍」的检查项；如本项目新增教训，追加到表中。
6. 本文件只写规范与模板，不写任何具体论文的数据与结论；具体数值一律留在项目内部文件中。
